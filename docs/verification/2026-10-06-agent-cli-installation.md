# 코딩 에이전트 설치 검증

2026-10-06 UTC(한국 시각 10-07), `feat/agent-cli-installation`의 실행 코드
`d710bc496a2a1296a8365d5de70c8027f7a47f94`를 검증했다.

## 네이티브 패키지

[Desktop packages 실행 37484134322](https://github.com/zzanghyunmoo/TommyBrown/actions/runs/37484134322)은
`test_agent_installers=true`로 실행했다. 설치 대상은 GitHub가 제공하는 일회용
네이티브 러너의 사용자 계정이며, 개발자의 기존 CLI나 인증 정보를 사용하지 않았다.

| 환경 | 단위 검사 | 패키지·첫 실행 | 설치 UI·실제 설치·새 터미널·재시작 |
| --- | --- | --- | --- |
| Windows 2025 x64 | 122 통과, 3 건너뜀 | 통과 | 2 통과 |
| macOS 15 ARM64 | 121 통과, 4 건너뜀 | 통과 | 2 통과 |
| macOS 15 Intel | 121 통과, 4 건너뜀 | 통과 | 2 통과 |

세 환경에서 TypeScript, Biome, 패키지 생성 및 아카이브도 통과했다.
건너뛴 검사는 해당 OS에 적용되지 않는 검사와 별도 활성화가 필요한 기존
Antigravity 네이티브 요청 검사다.

첫 시도의 Intel 작업은 의존성 다운로드의 무결성·압축 해제 오류로 빌드 전에
실패했다. 동일 커밋의 실패한 작업만 새 러너에서 재실행했고 전체 실행이 성공했다.

설정 화면에서 미설치 상태인 세 CLI를 차례로 설치했다. 각 공식 설치 프로그램의
종료 후 실제 실행 파일의 `--version`으로 다음 버전을 확인했다.

| CLI | 설치된 버전 |
| --- | --- |
| Codex | `codex-cli 0.160.1` |
| Claude Code | `2.1.291 (Claude Code)` |
| Antigravity | `1.3.0` |

앱을 재시작하기 전에 새 PowerShell/Bash 터미널에서 `codex --version`,
`claude --version`, `agy --version`의 출력을 확인했다. 이어 앱을 완전히 닫고
다시 실행해 세 CLI가 모두 설치된 상태로 탐색되는지 확인했다.

## 실패와 복구 경로

- 실제 Electron main/preload 경계에서 알 수 없는 CLI ID를 거부한다.
- 제어된 설치 결과를 사용하는 데스크톱 검사로 미설치·진행·실패·재시도·완료,
  취소, 설정과 터미널 사이의 상태 공유를 확인했다.
- 서비스 검사로 기존 설치 유지, Node가 없는 기존 npm 설치의 오류 구분,
  중복·동시 설치 차단, 검증 실패, 로그 크기 제한과 종료를 확인했다.
- 실제 자식 프로세스를 사용해 비정상 종료, 제한 시간과 하위 프로세스 종료를
  확인했다. Windows PowerShell의 `Get-FileHash` 사용도 별도로 검사했다.
- 앞선 Windows 실제 설치에서 상속된 `PSModulePath` 때문에 Codex 공식 스크립트가
  `Get-FileHash`를 찾지 못했다. 설치 자식 환경에서 해당 변수를 제외한 뒤 같은
  공식 설치 경로가 통과했다. 로컬 재현에서는 이 오류가 나타나지 않았으므로
  실패 근거는 [실행 37481750950](https://github.com/zzanghyunmoo/TommyBrown/actions/runs/37481750950)이다.
- 설치 후 렌더러 상태와 터미널 생성이 완료되기 전에 검사하던 경합은 실제 상태와
  셸 프롬프트를 기다리도록 수정했다.

## 화면 및 기존 동작

최종 실행의 `evidence-windows-x64`, `evidence-macos-arm64` 아티팩트에서
실제 네이티브 창 캡처를 열어 설치 완료 카드와 세 CLI의 터미널 출력을 확인했다.
설치 실패·취소 화면의 밝은 테마와 어두운 테마도 앞선 패키지 검사에서 확인했다.
캡처는 무시된 로컬 디렉터리에만 보관한다.

Windows에서 기존 `settings.e2e.ts`, `cli-restart.e2e.ts`, `cli.e2e.ts`도 통과했다.
설정 복원, Fable 모델 이름, CLI 간 모델 매핑과 세션별 MCP 인수·인증 전달을
검사했다. 이 기존 라우팅 검사는 제어된 CLI/응답을 사용한다.

## 범위

실제 설치 검사는 로그인이나 유료 추론 요청을 실행하지 않는다. 공식 설치
프로그램이 사용자 PATH나 셸 설정을 갱신할 수 있고, 이미 열린 터미널은 새로
열어야 한다. 설치 취소는 진행 중 프로세스를 종료하며 이미 설치된 파일을
되돌리는 제거 기능은 아니다. Windows ARM64는 이번 실행 대상이 아니다.

기존 번들 크기 경고는 남아 있다. 현재 공개 v0.1.1에는 이 설치 기능이 없으며,
프로필 분리 PR #11 위에 쌓인 PR #12의 검증 결과다.
