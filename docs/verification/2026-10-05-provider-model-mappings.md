# 제공자 간 모델 매핑 검증

대상: Windows x64, Electron 44.5.1, CLIProxyAPI 8.0.10. 기능 브랜치는
`feat/provider-model-mappings`이며 선행 [PR #3](https://github.com/zzanghyunmoo/TommyBrown/pull/3)은 병합되었다.

## 동작

- OpenAI, Claude, Antigravity 모델을 같은 행에 등록하고 CLI별 실행 제공자를 선택한다.
- 여섯 방향 모두 계정 제공자별 별칭으로 라우팅한다. 원래 모델 ID는 유지한다.
- Claude의 Opus, Sonnet, Haiku 단축 이름은 서로 다른 행에 연결할 수 있다. 연결하지 않은 단축 이름은 선택한 세션 모델을 사용한다.
- 명령 복사와 작업 공간 터미널에 같은 변환을 적용하고 대상 제공자/모델을 표시한다.
- 저장과 재시작 복원, 중복 방지, 대상 모델 검증, 적용 실패 복구, 오래된 미리보기와 별칭 충돌의 실행 차단을 포함한다.

## 결과

| 검사 | 결과 |
| --- | --- |
| `bun run check` | 통과 |
| `bun run lint` | 통과 |
| `bun run test` | 18개 파일, 68개 테스트 통과 |
| `bun run package:windows` | 빌드 및 Windows 패키징 통과 |
| `bun run scripts/mapping-smoke.ts` | 실제 엔진의 세 제공자 별칭 등록, 원래 ID 유지, 재시작 복원 통과 |
| 패키지 대상 `bun run test:desktop` | 10개 시나리오 전체 통과, 46.6초 |
| `bun run doctor:react` | 64/100, 기존 오류 3개와 권고 14개; 아래 판정 참고 |

최종 패키지는 `release/windows-20261005124712553/TommyBrown-win32-x64/`이다.
패키지 main 번들 SHA256:
`02a58ade012082f967ead8b65fdd95dda8f0a585f526504ed824eac75b5d1e66`.

패키지 테스트는 실제 Windows 앱에서 예시 추가/취소, 필수 값 오류, 행 추가/삭제/저장,
여섯 방향의 명령 복사, 설정 복원, 게이트웨이 재시작을 확인했다. 실제 Windows PTY로
세 CLI의 테스트 실행 파일을 구동하여 여섯 방향의 모델 인수와 Claude/Antigravity 환경을
검사했다. 기존 브라우저 분할, 문서 편집, 커넥터, PTY 유지/종료, 오프라인 보관함,
단축키와 작업 탭도 통과했다.

소스 실행의 전체 검사에서는 9개가 통과하고 1개 캡처 단계가 실패했다. 저장된 main 상태만
확인한 뒤 렌더러 교체가 끝나기 전에 스크롤을 시작한 것이 원인이었다. 입력란 활성화를
기다리도록 동기화했고, 수정 후 최종 패키지에서 해당 검사와 전체 10개 검사가 통과했다.

## 화면 확인

1320×880과 960×640 Windows 창에서 계정/매핑 화면을 확인했다. 매핑 표의 좁은 영역은
가로 스크롤을 사용하고 저장/취소 버튼은 화면 안에서 접근 가능하다. 긴 모델 ID에는
전체 값 툴팁이 있으며 입력란에서 편집할 수 있다.

## 순차 리뷰

검토에서 설정 변경 이후 미리보기와 실행이 달라지는 경로를 찾아 revision 검사를 추가했다.
다른 제공자가 같은 내부 별칭을 노출하는 경우도 실행을 차단한다. Claude의 연결하지 않은
보조 모델은 선택한 세션 모델을 사용하여 기존 세션 동작을 유지한다. 세 단축 이름이 서로
다른 대상으로 설정되는 경우와 대상 열이 비어 있는 경우를 별도로 검증했다.

React Doctor의 기존 `connector-pane.tsx` 오류 3개는 작업 실행 함수의 콜백을 React 상태
갱신 함수로 오인하는 항목이다. 이번 변경의 반복 탐색 권고는 세 단축 이름과 최대 64행의
유한한 매핑에 해당한다. 별칭 적용 확인은 순차로 수행한다. 기존 Monaco 큰 청크 경고도
유지된다. 타입 검사, lint, 기능 테스트에는 실패가 없다.

## 검증 경계

이번 검사는 별도 데이터 디렉터리, 합성 계정, CLI 테스트 실행 파일을 사용했다. 실제
제공자의 추론 성공이나 세 제공자 계정의 권한/할당량을 새로 검증한 결과는 아니다.
사용자의 토큰, 전역 CLI 설정, 기존 계정 파일은 테스트에서 변경하지 않았다.
