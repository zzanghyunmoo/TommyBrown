# Shared MCP gateway checkpoint

Date: 2026-10-06. Windows x64, Electron 44.5.1, MCP SDK 1.31.0.

## Observed behavior

The desktop starts a loopback gateway and supplies one `tommybrown` MCP server to
each terminal. The selected connector IDs determine that terminal's tool catalog.
Claude Code uses a configuration file, Codex uses launch overrides and a token
environment variable, and native Antigravity discovers an app-owned plugin via
`--add-dir`. The app's PowerShell wraps all three CLI commands with these profiles.
No global CLI configuration was changed.

| Surface | Result |
| --- | --- |
| Claude Code, connected OpenAI account | Called upstream `read_nonce` once through the gateway; returned the generated nonce |
| Codex, isolated CLI configuration, connected OpenAI account | Discovered the namespaced tool, called `read_nonce` once, returned the generated nonce |
| Antigravity 1.2.17, connected OpenAI account | Initialized MCP and listed tools; did not call the tool |
| Native Windows PowerShell inside packaged app | All three commands resolve to configured functions; `codex mcp get tommybrown --json` reports the loopback server and token environment variable |
| Disconnect selected connector | Owned terminal exits, old credential receives HTTP 401, session configuration directory is removed |
| Desktop restart | Gateway restarts; active session count is zero |

The nonce was generated by a local upstream fixture and was absent from the model
prompt. Success requires an observed upstream `tools/call` and the same nonce in
the CLI's final response. Tool-list discovery alone does not count as invocation.
The upstream fixture required its own bearer token, which was absent from every
child launch profile and managed MCP configuration.

## Antigravity blocker

The native CLI loads `.agents/plugins/tommybrown/mcp_config.json` from its added
workspace. It prefixes that server as `tommybrown_tommybrown`. Literal bearer headers
work; `${VARIABLE}` and `${env:VARIABLE}` header interpolation did not work locally.

With `AGY_LLM_GATEWAY_WIRE_PROTOCOL=openai`, captured model requests contained
messages, model and streaming fields but no tool declarations. A controlled streaming
response containing `tool_calls` was not executed; the next request reported that
the model output contained neither text nor tool calls. Real OpenAI responses also
reported that the listed MCP tool had no callable dispatch tool. Changing the model
name or removing the sandbox flag did not resolve this. Alternative unverified wire
protocol values failed eligibility checks; they were not shipped.

This is an unresolved native CLI/model-transport limitation, not a successful
three-CLI tool execution result. The feature must remain draft while that requested
acceptance criterion is outstanding. No Google login was initiated and no blanket
tool-approval bypass was enabled.

## Review and remaining scope

Sequential main-thread review covered credential boundaries, stale credentials,
disconnect ordering, error propagation, argument transport and requirement completeness.
It fixed cleanup ordering so a temporary-file deletion failure cannot prevent the
owned terminal from being killed. Cleanup can be retried while access is already revoked.
No independent reviewer was used under the workspace's sequential-agent policy.

MCP resources, prompts and an upstream OAuth flow are outside this change. The
Antigravity OpenAI invocation blocker is an unmet requested behavior, not a deferred
optional improvement. Existing provider/model mappings remain intact.
